# Smart Search Reader

متن‌خوان فارسی با جست‌وجوی زنده، پیشنهاد کلمه و قابلیت استفادهٔ آفلاین.

## اجرا

Node.js نسخهٔ **24** لازم است. نسخه‌های وابستگی در `package-lock.json` ثبت شده‌اند.

```sh
npm ci
npm run dev
```

برای بررسی PWA از نسخهٔ production استفاده کنید:

```sh
npm run build
npm run preview
```

آدرس پیش‌فرض پیش‌نمایش: `http://localhost:4173`.
پوشهٔ `dist` خروجی آمادهٔ استقرار است. آن را روی یک میزبان فایل استاتیک با HTTPS قرار دهید؛ فایل HTML را با دوبار کلیک و پروتکل `file://` باز نکنید. مسیر پایه نسبی است و امکان استقرار در زیردایرکتوری وجود دارد.

## رفتار برنامه

- جست‌وجو بلافاصله در عنوان بخش‌ها و پاراگراف‌های متن نمونه انجام می‌شود. عنوان کلی سند و نوشته‌های رابط جزو محدودهٔ جست‌وجو نیستند.
- تمام تطابق‌ها هایلایت می‌شوند. تطابق فعال رنگ و نشان متفاوت دارد و به مرکز صفحه اسکرول می‌شود.
- وقتی بیش از یک تطابق وجود داشته باشد، فلش‌های بالا و پایین نمایش داده می‌شوند. حرکت پس از آخرین نتیجه به اولین نتیجه برمی‌گردد و برعکس.
- شمارندهٔ بالای صفحه موقعیت فعال و تعداد کل را نشان می‌دهد. کنار هر بخش نیز تعداد تطابق‌های همان بخش دیده می‌شود.
- پیشنهادها از واژگان همان سند استخراج می‌شوند؛ ابتدا واژه‌های پرتکرارتر و حداکثر پنج پیشنهاد نمایش داده می‌شود.
- جست‌وجو نسبت به بزرگی حروف لاتین حساس نیست. «ی/ي/ى»، «ک/ك» و فاصله/نیم‌فاصله معادل‌اند. اعراب و کشیده نادیده گرفته می‌شوند.
- جست‌وجوی عبارت و بخشی از کلمه پشتیبانی می‌شود. عبارت باید داخل یک عنوان یا پاراگراف باشد؛ تطابق بین دو پاراگراف و تطابق‌های هم‌پوشان محاسبه نمی‌شوند.
- ورودی خالی، عبارت ناموجود و یک نتیجهٔ منفرد حالت‌های مستقل دارند. عبارت جست‌وجو متن ساده است؛ regex یا HTML اجرا نمی‌شود.

متن ورودی در صورت مسئله مشخص نشده بود؛ برای همین، یک سند ثابت و محلی انتخاب شده است. محتوای آن در `src/data/document.ts` قابل جایگزینی است. ویرایشگر متن، بارگذاری فایل، حساب کاربری و ارتباط با سرور در دامنهٔ این تمرین نیستند.

## صفحه‌کلید و دسترس‌پذیری

| کلید          | رفتار در ورودی جست‌وجو                           |
| ------------- | ------------------------------------------------ |
| بالا / پایین  | مرور پیشنهادهای موجود                            |
| Enter         | انتخاب پیشنهاد فعال؛ در غیر این صورت نتیجهٔ بعدی |
| Shift + Enter | نتیجهٔ قبلی، وقتی پیشنهاد فعالی انتخاب نشده باشد |
| Escape        | بستن پیشنهادها بدون پاک شدن عبارت                |
| Tab           | حرکت طبیعی بین ورودی، دکمه‌ها و پیوندها          |

پیشنهادها از الگوی combobox/listbox استفاده می‌کنند؛ فوکوس هنگام انتخاب روی ورودی باقی می‌ماند. تغییر شمارنده با `aria-live` اعلام می‌شود. صفحه راست‌به‌چپ، واکنش‌گرا و دارای پیوند پرش به متن است. تنظیم `prefers-reduced-motion` انیمیشن و اسکرول نرم را غیرفعال می‌کند.

## آفلاین و نصب

1. نسخهٔ production را یک بار با اتصال اینترنت باز کنید و منتظر «آمادهٔ استفادهٔ آفلاین» بمانید.
2. اینترنت را قطع و صفحه را دوباره بارگذاری کنید. متن، فونت، جست‌وجو و پیشنهادها همچنان کار می‌کنند.
3. در مرورگرهای پشتیبان، از «نصب برنامه» یا گزینهٔ نصب در منوی مرورگر استفاده کنید.
4. در Safari روی iPhone/iPad، از Share → Add to Home Screen استفاده کنید.

فونت و تمام منابع برنامه محلی‌اند. Service Worker هنگام build توسط `vite-plugin-pwa` ساخته می‌شود و فایل‌های production را precache می‌کند. به‌روزرسانی با تأیید کاربر اعمال می‌شود تا مطالعه ناگهان قطع نشود. Service Worker در حالت توسعه فعال نیست. نصب به مرورگر و سیستم‌عامل وابسته است و به HTTPS یا localhost نیاز دارد؛ IP شبکهٔ محلی با HTTP برای این بررسی کافی نیست.

عبارت جست‌وجو پس از بارگذاری مجدد پاک می‌شود؛ این تمرین نیازی به ذخیرهٔ تاریخچه یا دادهٔ شخصی ندارد.

## ساختار و تصمیم‌های فنی

```text
src/
  data/document.ts              متن نمونه
  lib/search.ts                 جست‌وجو و پیشنهاد؛ توابع مستقل از UI
  lib/search.test.ts            تست نرمال‌سازی و موقعیت تطابق‌ها
  lib/content.ts                ساخت یک‌بارهٔ ایندکس و واژگان
  components/SearchBox.tsx      ورودی و تعامل با پیشنهادها
  components/HighlightedText.tsx رندر امن قطعه‌های متن
  components/AppStatus.tsx      وضعیت اتصال، آفلاین و به‌روزرسانی
  hooks/useInstall.ts           چرخهٔ رویداد نصب مرورگر
  App.tsx                      ترکیب صفحه و موقعیت نتیجهٔ فعال
  styles.css                   طراحی، RTL و حرکت کاهش‌یافته
tests/reader.spec.ts            تست مرورگری روی build واقعی
```

- **React و TypeScript با strict:** وضعیت فقط شامل عبارت جست‌وجو و موقعیت نتیجه است؛ نتایج و پیشنهادها از آن‌ها مشتق می‌شوند.
- **بدون کتابخانهٔ جست‌وجو، state manager یا UI kit:** دامنهٔ مسئله کوچک است. React و React DOM تنها وابستگی‌های مستقیم runtime هستند؛ ابزار PWA کد لازم برای Service Worker را در build تولید می‌کند.
- **ایندکس یک‌باره:** متن ثابت پیش از رندر نرمال می‌شود. با هر ورودی، همان ایندکس جست‌وجو می‌شود؛ درخواست شبکه وجود ندارد.
- **حفظ offset متن اصلی:** حروف حذف‌شده و فاصله‌های ادغام‌شده طول متن را تغییر می‌دهند. نگاشت بازه‌های متن نرمال‌شده به متن اصلی از هایلایت اشتباه جلوگیری می‌کند.
- **جست‌وجوی literal:** `indexOf` برای این سند کافی است. متن با گره‌های React و `<mark>` رندر می‌شود و `dangerouslySetInnerHTML` وجود ندارد.
- **بازخورد فوری، اسکرول کنترل‌شده:** هایلایت فوری است؛ اسکرول ۱۶۰ میلی‌ثانیه بعد از آخرین تغییر انجام می‌شود تا تایپ سریع باعث اسکرول‌های پیاپی نشود. تایمر هنگام تغییر یا unmount پاک می‌شود.
- **CSS و API مرورگر:** انیمیشن سبک و `scrollIntoView` نیاز را پوشش می‌دهند. Web Worker یا virtualization برای اندازهٔ این سند لازم نیست؛ برای اسناد بسیار بزرگ باید بر اساس اندازه‌گیری دوباره تصمیم گرفت.

## بررسی کیفیت

```sh
npm run lint
npm test
npm run build
npx playwright install chromium
npm run test:e2e
```

یا پس از نصب مرورگر، `npm run check` همهٔ مراحل را به ترتیب اجرا می‌کند. تست‌های مرورگری نیازمند build قبلی هستند و سرور پیش‌نمایش را خودکار اجرا می‌کنند.

تست‌های واحد، نرمال‌سازی فارسی، offsetهای UTF-16، اعراب، ایموجی، عبارت‌ها، ورودی خالی، نویسه‌های ویژه و رتبه‌بندی پیشنهادها را پوشش می‌دهند. تست‌های مرورگر روی پروفایل دسکتاپ و موبایل اجرا می‌شوند و هایلایت، شمارنده، حرکت حلقوی، انتخاب پیشنهاد با صفحه‌کلید، نبود اسکرول افقی، manifest و بارگذاری مجدد آفلاین را بررسی می‌کنند.

نصب واقعی روی دستگاه iOS و Android نیازمند بررسی دستی روی همان دستگاه است؛ شبیه‌سازی اندازهٔ موبایل جای آن را نمی‌گیرد.

## مرور سریع برای ارزیابی

1. «جستجو» را تایپ کنید؛ تطابق‌های متن و شمارنده‌های بخش‌ها را بررسی کنید.
2. با فلش قبلی از اولین نتیجه به آخرین نتیجه بروید؛ سپس با فلش بعدی برگردید.
3. «خوا» را تایپ و پیشنهاد را با پایین و Enter انتخاب کنید.
4. «كلمه» و «می توان» را امتحان کنید تا تطابق فارسی و نیم‌فاصله را ببینید.
5. «PWA» را جست‌وجو کنید؛ تنها یک نتیجه وجود دارد و فلش اضافی نمایش داده نمی‌شود.
6. یک عبارت ناموجود وارد کنید و سپس جست‌وجو را پاک کنید.
7. در نسخهٔ production، پس از آماده شدن آفلاین، اتصال را قطع و صفحه را reload کنید.
